# M6.1 平台基座实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 subagent-driven-development（推荐）或 executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法跟踪进度。

**目标：** 完成 M6.0 基线收口与 M6.1 后端平台基座：LLM Profile、Agent 绑定与能力矩阵、Prompt/Skills 运行时注入、用量台账、配置审计、最小认证、LangGraph 节点注册。

**架构：** 新增 `control/` 服务层承载配置与台账；`agents/runtime.py` 组装 Agent 上下文；`agents/llm.py` 扩展双协议与 Profile 构造；`orchestrator/registry.py` 提供节点元数据；`web/control_api.py` 暴露 HTTP 契约。所有新表由幂等 DDL 懒加载。

**技术栈：** Python 3.11+、FastAPI、LangGraph、PostgreSQL 16 + pgvector、cryptography（Fernet）、httpx（Anthropic 兼容端点）、pytest。

**规格：** `doc/2026-10-20-m6.1-platform-foundation-spec.md`（审计：`...-spec-audit.md`）

## 全局约束

- 密钥永不出现在代码、文档、测试夹具、日志、审计、导出中；读接口只返回前 8 位 + `…`。
- 所有 DDL 使用 `IF NOT EXISTS` / `ADD COLUMN IF NOT EXISTS`，可重复执行。
- 无数据库时控制面 API 降级为空集/503，运行时回退 `.env` 或 `llm=None`，不得崩溃。
- `LLMClient` 保留现有构造签名与 `from_config()`；新参数全部可选。
- 现有 API 路径与响应字段保持兼容；新增字段为增量。
- Graph 主链路语义不变；仅新增 runtime 注入，且不得破坏只接受 `state` 的 stub 节点。
- 默认 `AUTH_ENABLED=false`；认证测试单独开启，不影响现有 146 个测试。
- 每个任务结束运行对应测试；里程碑末运行 `uv run pytest -q`。

## 审查重点（Review Focus）

1. **stub 节点兼容**：`graph._wrap` 只能用签名 introspection 注入 `runtime`；只接受 `state` 的 lambda 必须继续工作。
2. **历史多 active Prompt**：建唯一索引前必须收敛历史数据；写入路径必须先清 active 再插入。
3. **密钥泄露**：Profile 读、审计 before/after、错误信息、日志、`__repr__` 都不得出现明文；空密钥更新必须保留原值。
4. **OpenCode Go 协议**：模型前缀规范化、`x-opencode-session`、逐模型 Anthropic `/messages` 切换、`ModelProtocolUnsupported` 不盲目重试。
5. **认证旁路**：`AUTH_ENABLED=true` 时所有 `/api/*`（login/health 除外）必须校验；viewer 写配置必须 403。
6. **无库降级**：新表不存在、连接失败时 API 与扫描流程不能 500。
