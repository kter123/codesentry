# M6.0 + M6.1 平台基座规格（后端）

> 日期：2026-10-20。上游：`docs/superpowers/specs/2026-10-19-requirements-v2.md`（FR-20/21/22/23/24/25/27/29/30）、`2026-10-20-opencode-go-provider-design.md`。
> 本轮遵循 `agent.md` §0 八步流水线；本文档是 M6.1 的实现规格，不含 Vue 3 页面与沙箱/PoC 链路。

## 1. 目标

把「LLM / Agent / Prompt / Skills」从静态配置与桌面代码，变成**可配置、可绑定、可观测、可复现**的控制面，并修复 M6.0 基线回归。

完成标准：

1. Agent 通过绑定解析到具体 LLM Profile；未绑定/不可用时按 fallback → 默认 → `.env` 降级。
2. Triage/PoC 节点实际使用生效 Prompt + Skills 注入 + 绑定模型，不再是 `llm=None`。
3. 每次扫描固定 `prompt_snapshot`、`skill_snapshot`、`llm_snapshot`。
4. 每次 LLM 调用写入 `llm_usage`，可按 profile/agent/scan/day 聚合。
5. 所有配置写操作写 `config_audit`，密钥脱敏。
6. 最小认证与三角色可启用；未启用时仅允许本地回环访问。
7. 现有测试全绿，新增测试覆盖上述链路。

## 4. 架构

```
FastAPI 控制面
  ├─ /api/llm-profiles      LLM 配置与探测
  ├─ /api/agents            Agent 绑定/能力/统计/干跑
  ├─ /api/usage             token/成本聚合与配额
  ├─ /api/audit             配置变更
  ├─ /api/prompts /skills   Prompt 激活、Skills 预览
  └─ /api/auth              登录/登出/me（可开关）
        │
control/ 服务层
  profiles.py  routing.py  usage.py  audit.py
  agent_config.py  prompts.py  skills.py  auth.py
        │
agents/runtime.py  →  AgentRuntime(llm, system_prompt, skills_block, capabilities)
        │
orchestrator/registry.py  →  graph 节点注册与 runtime 注入
        │
PostgreSQL（业务 schema）
```

模块边界：

- `control/` 只做配置与台账，不调用 graph。
- `agents/runtime.py` 只解析并组装上下文，不执行节点逻辑。
- `agents/llm.py` 只负责协议调用、重试、用量；不读业务表（由 `for_agent` 调 `control.profiles`）。
- `web/control_api.py` 只做 HTTP 契约与错误映射。
- `orchestrator/registry.py` 只维护节点元数据；`graph.py` 仍是唯一组图入口。

### 6.4 Auth（可开关）

`CODESENTRY_AUTH_ENABLED=false`（默认）时所有接口按现有本地模式开放；`true` 时：

- `POST /api/auth/login`（JSON 或表单）→ 设置 HttpOnly Cookie。
- `POST /api/auth/logout`、`GET /api/auth/me`。
- 角色：admin（全部）、analyst（扫描/复核/读配置）、viewer（只读）。
- 配置写接口要求 admin；扫描创建/复核要求 analyst 及以上。
- API Token：`Authorization: Bearer cs_...`，scope 校验。
- 密码使用 `hashlib.scrypt`；JWT 使用 HS256 + `CODESENTRY_SECRET_KEY`，12h 过期。
- 首个管理员：`codesentry user create --admin` 或 `CODESENTRY_ADMIN_PASSWORD` 引导。

## 7. 运行时接线

### 7.1 AgentRuntime

```python
@dataclass
class AgentRuntime:
    agent: str
    enabled: bool
    llm: LLMClient | None
    system_prompt: str
    prompt_version: int | None
    prompt_fallback: bool
    skills: list[Skill]
    skills_block: str
    warnings: list[str]
    capabilities: dict
    model_role: str

    def system(self) -> str: ...      # prompt + skills_block
    def snapshot(self) -> dict: ...   # 版本/能力/模型
```

`prepare_agent(agent, scan_id, role=None)`：

1. 读 `agent_configs`（缺失用默认值）。
2. `enabled=false` → `llm=None`，节点返回 skipped 语义。
3. `load_prompt(agent)` → 生效 Prompt；失败回退种子并告警。
4. `load_assigned_skills(agent)` → 按 priority、version_pin 解析 → `build_context_block`。
5. 能力矩阵：`poc_gen` 在 `POC_RUN=off` 时关闭 network/shell/poc_exec。
6. `LLMClient.for_agent(agent, role)`；失败时 `llm=None` 并告警（节点降级）。

**session_id 规则**：`scan-{scan_id}-{agent}-{profile_id}`；无扫描上下文时用 `probe-{uuid4().hex[:8]}`。该值注入 Provider 的 `extra_headers["x-opencode-session"]`，不得包含用户名、密钥或代码内容。

### 7.2 节点注入

`graph._wrap`：

- 通过 `inspect.signature` 判断节点是否接受 `runtime` 参数；接受则注入，否则保持 `fn(state)`（兼容现有测试 stub）。
- `runtime.warnings` 追加到 `state.messages`。
- `runtime.snapshot()` 合并到节点 update 的 `prompt_versions` / `skills_snapshot`。
- 节点耗时/tokens 仍走 `node_run` 与 `BudgetGuard`。

`run_triage(state, llm=None, runtime=None)`：

- `system = runtime.system()`；`llm = runtime.llm or llm`。
- 无 LLM → 现有「未验证保留」逻辑。
- 返回 `prompt_versions` / `skills_snapshot` 增量。

`run_poc_gen(state, llm=None, runtime=None)`：

- 同源注入；能力 `poc_exec=false` 时强制 `plausible`。
- `POC_RUN=off` 行为不变。

Prompt 写入约束：`create/activate/rollback` 必须在同一事务内先 `UPDATE prompt_versions SET active=FALSE WHERE agent=%s`，再插入/激活目标版本；否则唯一索引 `prompt_versions_one_active` 会冲突。

### 7.3 快照

扫描创建时写入：

```json
{
  "prompt_snapshot": {"triage": {"version": 3, "sha256": "..."}},
  "skill_snapshot": {"triage": [{"name": "x", "version": 2, "sha256": "..."}]},
  "llm_snapshot": {"triage": {"profile_id": 1, "provider": "opencode-go", "fast_model": "...", "deep_model": "..."}}
}
```

快照在扫描创建时固定，运行中配置变更不影响本次扫描（NFR-2）。

## 8. 安全

1. 密钥：Fernet（`CODESENTRY_SECRET_KEY` 派生）或 `work_dir/.secret_key`（0600，自动生成）；读接口掩码；日志/审计/导出脱敏。
2. Profile 删除保护：被 Agent 绑定 → 409。
3. 认证开启后，所有 `/api/*`（除 login/health）要求身份；配置写要求 admin。
4. 默认监听 127.0.0.1；绑定非回环地址且未启用认证时，启动日志显式警告（本轮不强制退出，避免破坏现有部署）。
5. 上传/切片/PoC 现有防护不变。
6. `tests/test_opencode_probe.py` 不再包含真实密钥。
7. 旧密钥已存在于 git 历史（`a44fa1a`、`0e2eb11`）：本轮只清理工作区；历史清理需单独授权，且该密钥应立即在 OpenCode 控制台轮换。

## 9. 兼容与迁移

- DDL 全部 `IF NOT EXISTS`；历史多 active Prompt 自动收敛。
- `LLMClient` 保留现有位置参数与 `from_config()`；新增参数全部可选。
- 现有 API 路径与响应字段保持；新增字段为增量。
- Graph 主链路不变；仅新增 runtime 注入。
- 无库环境下：控制面 API 返回 503/空集，不崩溃；运行时回退 `.env` 或 `llm=None`。

### 9.1 Schema 懒加载

`control/bootstrap.py::ensure_control_schema()` 执行幂等 DDL（进程内缓存，失败不抛出，返回布尔）：

- 首次控制面 API 调用、`run_scan_graph` 开始时调用；
- 测试可直接调用以确保新表存在；
- 与 `codesentry init-db` 共用同一份 DDL，避免双源。

6. 配置写操作在 `config_audit` 有 before/after，且不含完整密钥。
7. `AUTH_ENABLED=true` 时未登录访问配置接口 401，viewer 写配置 403。
8. `/api/health` 返回 DB/引擎/Docker 状态，单项失败不影响整体。

## 12. 风险

| 风险 | 缓解 |
|---|---|
| Anthropic 协议适配未引入 SDK | 用 httpx 直连 `/messages`，契约测试覆盖；失败降级 fallback |
| 现有测试依赖无认证模式 | 默认 `AUTH_ENABLED=false`；认证测试单独开启 |
| 历史 Prompt 多 active 迁移失败 | DDL 先收敛再建唯一索引；失败时记录并跳过索引 |
| 无库环境 | 所有控制面写入 try/except；运行时回退 `.env` |
| runtime 注入破坏 stub 节点 | 通过签名 introspection，仅对声明 `runtime` 的函数注入 |
| 密钥轮换遗漏 | 提供主密钥派生；文档提示轮换后需重加密；本轮不做批量重加密任务 |
