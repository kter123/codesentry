## 三、遗留问题（转入计划）

1. **source/sink 规则种子**：规格只规定来源（Semgrep/Joern/内置表），未列出首批规则。G1 计划需给出最小规则集（Java: `Runtime.exec`、`Statement.execute`、`ObjectInputStream`、`File` 路径、SSRF 客户端；Python: `eval/exec/pickle/subprocess/os.system`）。
2. **Java 权限规则覆盖度**：Spring Security、Shiro、自研拦截器三类之外的长尾（如网关配置）需在 G1 用样例标注「其他」而非硬猜。
3. **大图性能**：`graph_build` 位于 scan 之前，可能拉长首节点时间；G1 需记录 10 万文件级样例的构建耗时与内存。
4. **前端图组件选型**：ECharts 力导向在 2000+ 节点下的交互帧率需在 G4 实测；不达标时切 Cytoscape.js。

## 四、风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 多语言 AST 覆盖不全 | 图稀疏、误判不可达 | 未解析调用单独计数并展示；不把「图里没有」等同于「不可达」 |
| 权限判定误报 | 高价值结论不可信 | 每条结论强制带证据与 `mismatch` 标记；无证据归「其他」 |
| 图版本与扫描版本错配 | 报告不可复现 | `scans.graph_build_id` 固定；报告引用 build 统计 |
| 管理面迁移影响现有测试 | 回归 | 双读过渡；先加表后切调用点 |
| LLM 熔断误伤 | 扫描中断 | 半开试探 + 手动恢复 + 软阈值 3 次 |

## 五、验收可行性

- 「同一仓库两次构建节点/边一致」可自动化。
- 「六语言样例产出节点/边」需要六个最小样例仓库，G2 计划纳入。
- 「triage 证据含真实路径」需要先把 retrieval 的假向量移除，顺序正确。
- 「kvf-admin 端到端」作为 V1，依赖 G1–G4 与 M1–M2 完成。
