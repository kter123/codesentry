## 3. 审计发现与回写

### P1（必须修）Prompt 写入统一走服务层

`admin_api.py` 现有 `create_prompt` / `rollback_prompt` 直接插入 `active=TRUE`。计划任务 8 只创建 `control/prompts.py`，未要求替换调用点。回写：任务 8 增加“修改 `admin_api.py` 使用 `control.prompts`”，并补测试断言激活唯一。

### P2（必须修）扫描行重复插入

`server._insert_scan` 插入一次，`run_scan_graph` 又插入一次，导致同一次 UI 上传产生两行 `scans`，快照与用量无法归属。回写：

- `run_scan_graph(repo, OSS, out_dir, scan_id: int | None = None)`；
- 若传入 `scan_id` 则复用并更新，不再插入；
- Web 上传传入已插入的 `scan_id`；
- 新增测试断言一次上传只产生一行扫描。

### P3（必须修）认证路径策略

回写任务 12：在 `control/auth.py` 定义 `PATH_POLICY`：

- 公开：`/api/auth/login`、`/api/health`、`/openapi.json`、`/docs`；
- 读：所有 `GET /api/*` 需任意已认证角色；
- admin：`POST/PUT/DELETE` 命中 `llm-profiles|agents|prompts|skills|rules|settings|users|api-tokens`；
- analyst+：`POST /api/scans`、`/api/scans/*/resume`、`/api/reviews/*`；
- CI Token：`scan:read` 允许 GET 扫描/报告；`scan:write` 允许创建扫描。
- 认证测试必须覆盖旧接口 `/api/settings/llm` 的写保护。

### P4（应修）文档与环境示例

回写任务 17：`.env.example` 增加 `CODESENTRY_SECRET_KEY`、`CODESENTRY_AUTH_ENABLED`、`CODESENTRY_OPENCODE_GO_*` 占位；README 增加启动与认证说明。

### P5（应修）Review 范围

回写任务 15/16：第一轮聚焦正确性/安全（密钥、认证、迁移、协议）；第二轮聚焦架构/兼容/降级（模块边界、无库、旧 API、测试覆盖）。输出格式：finding 编号、严重度、文件:行、复现、建议、结论（confirmed/rejected）。

### P6（应修）mypy 判定

回写任务 14：先记录基线 `uv run mypy src 2>&1 | tee /tmp/mypy-before.txt`，实现后对比；新增错误必须为 0，既有错误数不得增加。

## 4. 类型一致性

- `AgentRuntime.snapshot()` 返回 dict，被 `graph._wrap` 合并到 `prompt_versions/skills_snapshot`；与 `AuditState` 字段一致。
- `LLMClient.for_agent(agent, role, scan_id)` 与 `resolve_profile(agent)` 参数一致。
- `control.profiles.LLMProfile` 与 DDL 字段一一对应，含 `model_prefix_policy`。
- `record_usage` 参数与 `llm_usage` 列一一对应。
- `capability_allows` 与 `AGENT_DEFAULTS.capabilities` 键一致（`engines/network/shell/poc_exec`）。
